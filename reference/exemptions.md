# coded-comments: exemptions

Everything is coded or deleted except four kinds. Other prose is FREE.

1. **Prose doc on a truly exported declaration.** Your host file gives the test; the visibility keyword alone is not
   enough. If it cannot be decided, report UNKNOWN; never assume exempt. Cap: one summary line, then one line per
   param, return or raise the types do not carry. No example, workflow, history, ticket id, restated name or coded
   syntax. Over the cap, or only repeating the name: DOCCAP.
2. **Tool pragma.** Exempt only when the whole comment is a recognized pragma (host file). Prose after it moves to its
   own coded line.
3. **Legal text and file metadata.** Contiguous copyright, license or SPDX lines at the top of a file, with their
   continuation lines; a `#!` on line 1; an encoding or modeline in the first two lines. Other prose in the same
   block is classified on its own. A file-title banner or a section divider is not a header.
4. **Generated marker** (`@generated`, `Code generated ... DO NOT EDIT.`, `<auto-generated>`, `automatically
   generated`) in a file's first lines: skip the file. A marker in the middle of hand-written code exempts only that
   line.

Never exempt: docs on private or internal declarations, banners, dividers, `TODO` or `NOTE` prose, commented-out code.
